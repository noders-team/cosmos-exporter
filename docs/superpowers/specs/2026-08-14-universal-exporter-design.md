# Универсальный cosmos-exporter: дизайн переработки

Дата: 2026-08-14. Статус: одобрен (вариант «переработка ядра с graceful degradation»).

## Цель

Экспортер должен корректно работать и на стандартных Cosmos SDK-сетях (Union,
Persistence, Cosmos Hub), и на кастомных форках (Sei), не перегружая ноду
запросами. Внешний контракт — эндпоинты, имена метрик, лейблы — сохраняется
полностью: прод-дашборды Grafana и конфиги Prometheus не трогаем.

## Диагностированные дефекты (что чиним)

1. **`getConsensusAddress()` (validator.go)** ищет валидатора по хардкоду типа
   ключа `cometbft/PubKeyBn254` (Union-специфика) и возвращает адрес *первого
   попавшегося* валидатора, а не запрошенного. На Sei (ed25519) не находит
   никого → missed blocks молча пропадают. Вдобавок отдаёт hex-адрес туда, где
   gRPC `SigningInfo` ждёт bech32.
2. **`validators.go`**: `bytes.Equal(consAddr, []byte(signingInfo.Address))`
   сравнивает сырые байты с bech32-строкой — совпадений не бывает никогда,
   missed blocks не работают ни на одной сети.
3. **`validators.go`**: `DelegatorShares.BigInt()` у `LegacyDec` возвращает
   внутреннее представление ×10^18 — метрика завышена на 12 порядков.
4. **`general.go`**: `BondedTokens.Int64()` паникует при переполнении int64 —
   роняет процесс на сетях с 18-decimal деномами.
5. **Нагрузка на ноду**: каждый scrape = веер параллельных gRPC-запросов без
   кэша и таймаутов; `/metrics/validator` дополнительно тянет весь validator
   set ради rank.
6. **`setDenom` падает `log.Fatal`**, если сеть не публикует `DenomsMetadata`
   (Sei) и флаги не заданы.
7. Невалидный `?address=` отдаёт 200 OK с пустым телом.

## Архитектура

Пакет остаётся `main`, файлы маленькие и по фичам.

### 1. Кэш + фоновое обновление (`cache.go`)

`MetricsCache` — ключ = эндпоинт + канонизированные query-параметры, значение =
отрендеренный текст метрик (`expfmt`) + время сбора.

Поведение (stale-while-revalidate):
- запись свежая (моложе `--refresh-interval`, дефолт 30s) → отдать из кэша,
  ноду не трогать;
- запись протухла → отдать протухшую немедленно, в фоне запустить одно
  обновление (singleflight — параллельные scrape'ы не порождают дубли);
- записи нет (первый запрос) → собрать синхронно.

Итог: нагрузка на ноду ≤ 1 сбор на эндпоинт за интервал, сколько бы
Prometheus'ов ни скрейпило. Хендлеры превращаются в
`collectX(ctx, ...) (*prometheus.Registry, error)`, HTTP-обвязка одна общая.

### 2. Универсальный консенсус-адрес (`consaddr.go`)

`consAddressFromValidator(validator, bech32Prefix) (string, error)`:
- `/cosmos.crypto.ed25519.PubKey` → `ed25519.PubKey.Address()`;
- `/cosmos.crypto.secp256k1.PubKey` → `secp256k1.PubKey.Address()`;
- неизвестный тип (bn254 у Union и будущие) → извлечь сырые байты ключа из
  protobuf-поля 1 в `Any.Value` (честный парс wire-формата, не магические
  срезы) → `sha256(key)[:20]` (правило адресации CometBFT);
- результат кодируется в bech32 с настроенным `ConsensusNodePrefix`.

Никаких запросов к Tendermint RPC на каждый scrape — всё выводится из данных,
которые уже пришли по gRPC. В `validators.go` сравнение с
`signingInfo.Address` идёт строкой bech32-к-bech32.

### 3. Graceful degradation вместо Fatal/молчания

- Все gRPC-вызовы — с `context.WithTimeout` (`--grpc-timeout`, дефолт 10s).
- Ошибка одного запроса = WARN в лог + пропуск конкретной метрики, не падение
  и не пустой ответ целиком (mint-модуль Sei с нестандартной инфляцией просто
  даст отсутствие `cosmos_general_inflation`).
- `setDenom`: нет `DenomsMetadata` → fallback на `staking.Params.BondDenom` с
  коэффициентом 1 и громким WARN («задайте --denom/--denom-exponent»); Fatal
  остаётся только если денома не удалось определить вообще никак.
- Невалидный `?address=` → HTTP 400 с текстом ошибки (вместо 200 и пустоты).

### 4. Числа

Все конвертации `Int`/`LegacyDec` → float64 через строку/`big.Float`, ни
одного `.Int64()` на суммах токенов. `LegacyDec` — через `.String()` (даёт
уже нормализованное значение). Совместимость: `cosmos_general_bonded_tokens`
и `_not_bonded_tokens` остаются в микроединицах (задокументированная
несимметрия, дашборды на неё завязаны).

### 5. Зависимости

cosmos-sdk v0.50.12 → **v0.53.8** (последняя стабильная ветка с классическими
import-путями; v0.54+ дробит SDK на отдельные go-модули без пользы для
клиентского кода). gRPC-протокол сетей не зависит от версии клиентского SDK.

## Тесты

- Unit (table-driven): деривация cons-адреса (ed25519/secp256k1/synthetic
  bn254), парс сырых байт из Any, конвертации Dec/Int, канонизация ключа кэша,
  stale-while-revalidate поведение кэша (fake clock), sanitizeUTF8.
- Интеграционные: fake gRPC-сервер (in-memory, `bufconn`) со staking/slashing/
  bank/mint/distribution, канонические ответы «стандартная сеть» и «Sei-подобная»
  (нет mint, нет DenomsMetadata, ed25519) → собрать метрики → сверить текст.
- Живая проверка на публичном Sei gRPC перед релизом.

## Вне скоупа

- Multi-tenant (несколько сетей одним процессом) — по-прежнему один процесс =
  одна сеть (bech32-конфиг Seal).
- Переименование метрик, новые эндпоинты, миграция на v0.54+.
